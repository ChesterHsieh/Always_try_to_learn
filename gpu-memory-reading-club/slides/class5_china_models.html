命題：效率不是加分項，是生存條件

出口管制下算力受限，逼出了這批實驗室的三個共同特徵。

1

架構層就為推論成本設計

不是「先訓練完再想怎麼服務」。MLA 這種注意力機制的發明動機，直接就是 HBM 頻寬帳單——這是最乾淨的架構 ⇄ 硬體 co-design 案例。

2

系統零件跟著開源

FlashMLA / DeepEP / DeepGEMM / EPLB / 3FS…… 新架構必須被 vLLM、SGLang 支援才有人用，開源 kernel 是讓自家架構進入生態的手段。

3

技術報告寫得很細，含失敗嘗試

MiniMax 那篇「為什麼 M2 退回 full attention」尤其可貴——負面結果比正面結果更難得，也更有教學價值。

02

承接前兩堂：同一個敵人，兩個方向

回到第一堂的那把尺：AI = FLOPs ÷ Bytes。decode 的 AI ≈ 1，所以 GPU 大半閒置。

框架的做法：動分子

把 batch 撐大撐滿 → 同一次權重讀取被更多 token 分攤 → AI ≈ B

· 分頁 KV / RadixAttention

· continuous batching

· chunked prefill / PD 分離

· cache-aware router

模型的做法：動分母

直接讓「每產一個 token 要搬的位元組數」變少

· 壓 KV（MLA）

· 少算（MoE 稀疏）

· 少看（稀疏/線性注意力）

· 降精度（FP8 / MXFP4）

兩邊在 roofline 上做的是同一件事：把那個點從左邊的記憶體牆推向右邊。差別只在一個從外面調、一個從裡面改——而模型端改的東西，框架端必須支援才跑得起來（所以他們把 kernel 也開源了）。

① 壓 KV

④ 一次多產

長 context 讓 attention 的 O(n²) 與 KV 的線性增長同時失控。兩條路的差別非常重要。

稀疏注意力

保留完整 KV，但每個 query 只看 top-k 個位置

· DeepSeek DSA / CSA + HCA

· MiniMax MSA

· GLM-5 的 DSA 式稀疏

· MiniMax Lightning Attention（M1）

· Qwen Gated DeltaNet（3:1 混合）

· Kimi KDA（69 層線性 + 24 層 full）

2026 的共識不是「線性取代 full attention」，而是「混合 + 稀疏」——下一頁看 MiniMax 為什麼這樣說。

最有價值的反例：MiniMax M1 → M2 → M3

M1 · 2025-06

Lightning Attention 混合（線性為主）+ CISPO RL

▶

M2 · 2025-10

▶

M3 · 2026

改走 MSA 稀疏注意力：宣稱 1M ctx 下 prefill 9×、decode 15× 快於 M2

「No Free Lunch」講了什麼（LMSYS 部落格 + MiniMax 官方文件）

① 評測會騙人

混合注意力在 MMLU / BBH / LongBench 上看起來沒問題，放大後才發現多跳推理明顯退化——把長文件裡散落的線索串起來的能力壞掉了。而要在困難任務上得到統計顯著訊號，所需算力是天文數字。

② 理論 FLOPs ≠ wall-clock

線性注意力的實作本身就是 memory-bound，即使在訓練時也吃不滿算力——完全是第一堂 roofline 的教訓：省下的是紙上的 FLOPs，不是牆上的時間。

「省算力的方法」，需要巨量算力才驗證得了——這個弔詭是效率研究最大的結構性障礙。

③ 卡在三個生產系統上（回扣第三堂）

這一頁是第三堂與第五堂的接縫：模型端改架構，會直接打壞框架端已經建好的東西。

KV cache

第三堂問題②

線性注意力的狀態對數值精度遠比 full attention 敏感 → 低精度存不了，量化那個旋鈕跟著失效

Prefix caching

第三堂問題②

線性狀態不像 KV 可以直接切片複用 → RadixAttention 的整套價值歸零

投機解碼

第三堂天花板①

在線性注意力骨幹上「仍是未解問題」——單請求延遲的唯一解法沒了

他們也試過滑動窗口混合，調過比例、RoPE 設定、層內/層間配置、sink token —— 在 agent 任務與複雜長文評測上一致地很差。

「理論複雜度更低」離「生產環境更快」隔著三層：kernel 效率、評測有效性、生態相容性。

旋鈕④ 一次多產、旋鈕⑤ 降精度

④ MTP（Multi-Token Prediction）

訓練時多預測幾步當額外訊號（更密的監督），推論時那些 head 直接當投機解碼的 draft。

驗證 k 個草稿 token：權重讀取 = 1 次（不變），FLOPs = k 倍　→　AI 從 1 變成 k

為什麼他們連 kernel 都開源？

這是最容易被忽略、但策略上最關鍵的一步——也是這堂課與第三、四堂真正的接縫。

困境：新架構如果沒有 kernel，就沒有人跑得動

MLA 不是標準 attention，vLLM / SGLang 原本的 FlashAttention kernel 直接用不了。MoE 的 all-to-all、FP8 GEMM、專家負載均衡也都一樣——開源模型權重卻沒有配套 kernel，等於發布了一台沒有輪子的車。

15

帶走三句話

1

架構決策就是硬體帳單

MLA 是為了 decode 的 HBM 頻寬而發明的注意力機制；MoE 稀疏度是為了每 token 的權重讀取量；MXFP4 QAT 是為了對齊 Blackwell 的 tensor core。這批模型不是「先訓練完再想怎麼服務」，成本從第一天就寫在架構裡。

2

五個旋鈕，一個目標

壓 KV / 少算 / 少看 / 一次多產 / 降精度——全都在回答「怎麼讓每產一個 token 少搬一點位元組」。這是第一堂 roofline 的分母，也是第三堂框架優化的另一半。

3

理論上更省 ≠ 實際上更快

MiniMax M2 退回 full attention 是 2025–26 最重要的負面結果：kernel 效率、評測有效性、生態相容性三關全過，一個「更有效率的架構」才真的更有效率。而驗證它需要的算力，正是它想省下來的那些。

前五堂：硬體 → 多卡 → 單機引擎 → 多機服務 → 模型架構。下一堂（最終章）把五個高度裝回一整排機櫃。
