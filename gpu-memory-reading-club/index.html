為什麼同一個模型，換個搬資料的方式就差十倍？

給會寫 PyTorch、但沒碰過 CUDA 與計算機組織的 data science／ML 工程師。從一張 GPU 的記憶體階層出發，一路走到上百張卡的推論叢集：每一堂都在回答「資料在哪、怎麼搬、誰在等誰」。

一把尺：Roofline算術強度 = FLOPs ÷ 搬動的 Bytes。低於 ridge point 就是 memory-bound，換更強的算力也沒用。
一張地圖：記憶體階層每離運算單元遠一站就慢一個數量級。瓶頸永遠是資料必經的最慢那段路。

六堂課

同一個敵人（decode 是 memory-bound），六個高度：硬體的尺 → 單卡到多卡 → 單機引擎 → 多機服務 → 模型架構 → 裝回機櫃。照順序讀，每一堂都接住上一堂留下的問題。

1

硬體 × Transformer一張卡本身

roofline、記憶體階層、GPU 的 SM／warp／tensor core，把 Transformer 放上機器：訓練、prefill、decode 各被誰卡住。最後看模型與硬體怎麼互相塑造（CNN → Transformer → 混合架構、TPU、Groq）。
